## Rules
No fabricated measurements or novelty claims. Separate observed calculations from hypotheses, and reject failed designs.

## Known prior art; novelty status
**Not novel at this stage.** Block-sparse attention, attention bounds, memory-side acceleration, and runtime-certified attention already have literature. Relevant 2026 research includes "Certified Block Screening for Adaptive Long-Context Attention", "Runtime-Certified Bounded-Error Quantized Attention", "Elastic Threshold Attention", and "Efficiently Approximating Attention Is Hard". ## Initial falsifiable research question
Can attention-block metadata reduce total key/value movement while certifying an output-error limit, and in which input regimes does this fail?

## Experiment (simulation; not a chip)
Reproducible NumPy baseline script: `processor_baseline.py`. Parameters: seed 20261103, 128 blocks, 32 keys per block, 64 dimensions, tolerance 0.02 (normed by maximum value-vector norm), 32-bit representations.

For each block, compute mean key c and maximum key radius r. Then every score is bounded above by `(q · c + ||q|| r)/sqrt(d)` by Cauchy–Schwarz. Evaluate blocks descending by this upper bound. Let U be a bound on total unvisited softmax mass and Z the visited exact mass. For visited-only output O_v and dense output O, `||O-O_v|| / max_i ||v_i|| <= 2U/(Z+U)` in exact arithmetic. The experiment stops when this certificate is <= 0.02.

### Results
| Synthetic input | KV blocks loaded | Total estimated memory traffic versus dense | Certificate | Observed normalized output error |
|---|---:|---:|---:|---:|
| Strongly clustered keys, concentrated attention | 1 / 128 | 2.368% | 0.00093911 | 0.00004268 |
| Unstructured independent Gaussian keys | 128 / 128 | 101.587% | 0 | 0 |

Estimated traffic includes all precomputed centroid/radius metadata and fetched float32 KV records per query. It excludes metadata construction, cache effects, transfers between physical memory tiers, runtime scheduling, interconnect cost, energy, clock frequency, and hardware area. The clustered case was deliberately constructed to be favorable; these numbers are **not** representative workload performance or chip-level speedup.

## Decision
The known method is sensitive to input structure. On unstructured data, metadata adds traffic. Do not claim a breakthrough; the promising result is purely a validation of the baseline and its failure mode.

## Next experiment and stop conditions
1. Test actual model KV-cache traces over multiple real models, tasks, layers, and context lengths; compare against full-attention and prior sparse-attention methods.
2. Verify worst-case output error and end-to-end model quality. Use multi-seed variance, not a single favorable instance.
3. Quantify metadata construction/update cost, total bytes and bandwidth, end-to-end latency, and energy. Record overhead at batch 1 and large batches.
4. Seek a genuinely new mechanism **only if** existing mechanisms cannot achieve the required trade-off and any proposed new mechanism differs materially from prior art.
5. Reject the concept if accuracy/latency/energy gains cannot be demonstrated on representative workloads after costs and baselines are included.

## Update: 2026-11-03 G2 feasibility (Anchor-Delta reuse)

Per `AGENTS.md`, G2 tested a **hypothesis**, not a claimed invention: cache per-page score bounds from an anchor query and reuse them for subsequent nearby queries via a safe query-difference/norm bound. On static synthetic KV, 1,120 query simulations and 900 supplemental property checks detected no violations within stated numerical tolerances. Favorable tightly correlated clustered queries gave **0.4286× the modeled per-query-metadata-and-KV-read traffic of the tested fresh screening baseline**; reducing correlation to 0.90 yielded **14.5102× worse traffic** in that regime. **Decision:** Formula feasible in exact arithmetic; not demonstrated novel, not robust, and **not authorized for hardware implementation** based on current evidence.
